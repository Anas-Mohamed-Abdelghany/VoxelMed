# VoxelMed

**AI-Powered Medical Image Viewer & Exploration Platform**

Built for the *AI for Real-World Response* Hackathon (Track 1 - Medical Sector) by Anas, Zyad, Hassan, and Nada.

---

## Overview

VoxelMed is a dual-architecture medical imaging application for viewing, segmenting, and exploring CT/MRI volumes. It provides clinical-grade multi-planar reconstruction, real-time 3D volume rendering, AI-powered organ segmentation, an AI biomarker risk engine, and interactive volume exploration tools.

**Two modes of operation:**

| Mode | Stack | Entry Point |
|------|-------|-------------|
| **Desktop** | PyQt5 + VTK + SimpleITK | `python -m backend.app` |
| **Web** | FastAPI + React + Three.js | Backend: `uvicorn backend.main:app` / Frontend: `npm run dev` |

**Web sidebar tabs:** `Main` | `Seg` | `Biomarkers` | `Report` | `3D Lab`

### Highlights

- **Multi-format import** — NIfTI, DICOM series (single slice or full study selection), JPG and PNG all load through the same 3D pipeline, on both web and desktop.
- **Robust DICOM series handling** — slices are grouped by series UID, the correct series is picked automatically from mixed selections, and geometry (spacing/origin) plus Hounsfield units are preserved, so segmentation and measurements stay accurate.
- **AI Biomarker Risk Engine** — two *independent* features: a pathology classifier driven by trained XGBoost model weights, and a standalone organ-volume measurement tool that never touches the model.
- **AI Report** — streaming LLM radiology report with grounded, clickable organ landmarks.
- **Fresh scan, fresh state** — uploading a new file automatically clears every analysis result from the previous scan (segmentation, biomarkers, volumes, measurements, report history).

## Supported Input Formats & Import Behavior

| Format | Extensions | How it is loaded | Where it works |
|--------|------------|------------------|----------------|
| NIfTI | `.nii`, `.nii.gz` | Native 3D volume; spacing, origin and direction preserved exactly | Web upload, desktop Open dialog |
| DICOM | one or many `.dcm` files | GDCM series reader → `(D, H, W)` volume in Hounsfield units (rescale slope/intercept applied) | Web upload (multi-select), desktop DICOM import |
| PNG | `.png` | Converted to grayscale and loaded as a single-slice volume `(1, H, W)` | Web upload, desktop Open dialog |
| JPEG | `.jpg`, `.jpeg` | Same as PNG | Web upload, desktop Open dialog |
| PNG | base64 | Generated by the API for slice/overlay/montage delivery | API responses only |

Unsupported file types are rejected with a clear `400` error naming the accepted extensions.

### How DICOM uploads are handled

A folder selection in a study almost always contains **more than one series** (a localizer/scout, alternative reconstructions, prior scans). The loader is designed so mixed selections can never silently corrupt the volume:

1. **Safe staging** — every uploaded file is written to an isolated temp directory with an index-prefixed name (`00000_IM0001.dcm`, …), so files with the same basename from different folders cannot overwrite each other.
2. **Series grouping (normal path)** — GDCM groups the files by `SeriesInstanceUID` and **the largest series wins**. Slices are ordered by image position automatically and the full geometry is taken from the series. Files belonging to other series are ignored and logged (`using the largest series (N slices); ignored M file(s) from other series`).
3. **Manual stacking fallback** — used when grouping is impossible: no series detected at all, or every "series" contains a single file (typical of anonymizers that regenerate a fresh `SeriesInstanceUID` for every slice). Each slice is read individually and sorted by `ImagePositionPatient` z → `InstanceNumber` → filename.
4. **Slice spacing** — derived from the median of consecutive `ImagePositionPatient` z differences; if positions are missing, the `SpacingBetweenSlices` tag is used, then `SliceThickness`, then 1 mm as a last resort. Correct spacing is what keeps radiomics volumes and segmentation resampling accurate.
5. **Single slice** — one `.dcm` file loads as a `(1, H, W)` single-slice volume; all three MPR views still work.
6. **Consistency check** — if slices with different pixel matrices must be stacked manually, the request fails with an explicit error instead of producing a garbled volume.

### 2D images (JPG / PNG)

Color images are converted to grayscale and treated as a **single-slice 3D volume** with normalized spacing `(1, 1, 1)`, identity origin and identity direction. This lets the entire existing 3D pipeline — windowing, MPR, segmentation, measurement, volume rendering — run unchanged on 2D input. On desktop, raster files are converted to a temporary NIfTI and reloaded through the same NIfTI path, so downstream AI features keep a valid volume path.

### Fresh scan, fresh state

Uploading a new file resets the backend session (fresh zero mask, no landmarks) **and** the frontend analysis state in one step: pathology results, organ volumes, errors, segmentation overlays/landmarks, measurement history and AI report messages are all cleared. The UI can never display results that belong to a previous scan.

### AI Biomarker Risk Engine (Web → `Biomarkers` tab)

The Biomarkers tab contains **two separate, independent features**. Each has its own button, its own backend endpoint and its own results section — measuring volumes never invokes the model, and the classifier never depends on the volume button.

#### Feature 1 — `Run Pathology Classifier`

**Pipeline:**

1. **Feature extraction** (`RadiomicsEngine.extract_all_biomarkers`) computes 14 quantitative biomarkers from the segmented volume:
2. **Inference** — the 14 features are passed to four trained **XGBoost classifiers** loaded from `backend/radiomics_pathology_engine.pkl`. A prediction probability ≥ 0.5 is reported as *High Risk*.
3. **Presentation** — each diagnosis card shows the human-readable label, risk percentage and an evidence string grounded in the measured biomarker (e.g. *"Liver-to-Spleen ratio: 0.83"*).

| # | Feature key | What it measures |
|---|-------------|------------------|
| 1 | `liver_vol_cm3` | Total liver volume = liver voxels × voxel volume (cm³) |
| 2 | `liver_mean_hu` | Mean attenuation of liver parenchyma (HU) — steatosis lowers it |
| 3 | `liver_std_hu` | Heterogeneity of liver attenuation |
| 4 | `liver_p10` | 10th percentile of liver attenuation |
| 5 | `liver_p90` | 90th percentile of liver attenuation |
| 6 | `liver_skewness` | Asymmetry of the attenuation histogram (0 for uniform regions) |
| 7 | `spleen_vol_cm3` | Spleen volume (cm³) |
| 8 | `spleen_mean_hu` | Spleen attenuation — the internal reference organ |
| 9 | `liver_spleen_ratio` | `liver_mean / spleen_mean`; below 1.0 suggests fatty liver |
| 10 | `liver_spleen_diff` | `liver_mean − spleen_mean` in HU |
| 11 | `l3_muscle_area_cm2` | Skeletal-muscle cross-sectional area at L3 (standard −29…150 HU window) |
| 12 | `l3_muscle_mean_hu` | Mean muscle attenuation at L3 — myosteatosis marker |
| 13 | `smi` | Skeletal Muscle Index = muscle area ÷ height² (cm²/m²) |
| 14 | `has_contrast` | 1 if the aorta mean exceeds 140 HU (contrast-enhanced scan) |

**Target pathologies (one model each):**

| Model key | Reported as | Evidence shown |
|-----------|-------------|----------------|
| `steatosis` | Hepatic Steatosis (Fatty Liver) | Liver-to-Spleen ratio |
| `sarcopenia` | Sarcopenia / Myosteatosis | L3 SMI (cm²/m²) |
| `hepatomegaly` | Hepatomegaly | Liver volume (cm³) |
| `splenomegaly` | Splenomegaly | Spleen volume (cm³) |

**Designed without hardcoded values:**

- The **feature order is read from the model bundle itself** (`bundle["features"]`, falling back to the estimator's `feature_names_in_`). Retraining with different features requires no code change; a biomarker missing from the extraction degrades to `0.0` instead of crashing.
- **Labels and evidence strings** come from `DIAGNOSIS_META`; unknown model names still render generically, so adding a fifth model later needs no frontend work.
- The **biomarker table** (name, value, unit, reference range) is generated from `BIOMARKER_META` by `biomarker_rows()` and rendered dynamically — no rows are hardcoded in React.
- If the model file is missing or fails to load, a deterministic **ACR clinical-rule fallback** produces the same four diagnoses from threshold rules.

#### Feature 2 — `Calculate Organ Volumes` (standalone, no model)

Measures the volume of **every organ present in the segmentation mask** — a pure measurement feature that is fully separated from the classifier:

- **Formula:** `vol_cm3 = voxel_count × (spacing_x × spacing_y × spacing_z) ÷ 1000`
- **No hardcoded organ list:** it iterates whatever the segmentation produced (label map, deduplicated by label ID), sorted by volume descending.
- **Result table:** Organ | Volume (cm³) | % of Total, plus the **total segmented volume**.
- Requires a segmentation mask first; returns a clear `400` otherwise.
- The response contains only `organ_volumes` and `total_cm3` — **no diagnoses, no model inference**.

> Patient height (default 1.75 m) is only used by the classifier, for the L3 SMI feature.

### AI Report (Web → `Report` tab)

Streaming LLM report generated through OpenRouter (`POST /api/ai/report`, Server-Sent Events). Requires `OPENROUTER_API_KEY` in `backend/.env`.

| Context mode | What the model sees |
|--------------|---------------------|
| Uploaded images | Only the images you attach yourself |
| Current slices | The 3 current MPR slices (axial / sagittal / coronal) |
| Full montage | A grid montage of **all** slices in every view |

Organ mentions in the generated report become **grounded, clickable landmarks** — clicking one navigates all views to that organ's centroid.

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/upload` | Upload one file (NIfTI / JPG / PNG) or many `.dcm` slices in a single request (multipart field `files`, repeated). Validates the extension, resets the session (fresh mask, no landmarks), returns shape/spacing/filename |
| `GET` | `/api/volume` | Current volume metadata: shape, spacing, origin, filename, restoration flag |
| `GET` | `/api/volume/data` | Volume downsampled to ≤128³ as base64 plus dims/spacing, mask and label colormap for the 3D view |
| `GET` | `/api/segmentation/mask3d` | Mask + label colormap + organ→label map only (refreshes the 3D overlay without re-sending the CT) |
| `GET` | `/api/slice/{view}/{slice_index}/base64` | Windowed PNG for `axial` / `sagittal` / `coronal`; query params `window_center`, `window_width`; returns PNG base64 + `max_slice` |
| `GET` | `/api/slices/montage/{view}/base64` | Grid montage of **all** slices in one view (AI Report context) |
| `GET` | `/api/segmentation/{view}/{slice_index}/base64` | RGBA segmentation overlay PNG for a slice |
| `POST` | `/api/segmentation/run` (alias `/api/segment`) | Run TotalSegmentator (`--fast`) or the built-in threshold fallback; writes mask, landmarks and `organ_to_label` |
| `POST` | `/api/segmentation/draw` | Brush / eraser / smart-brush edits on the mask |
| `POST` | `/api/landmarks/{organ_name}/navigate` | Centroid position of a segmented organ |
| `GET` | `/api/landmarks` | All organ centroids |
| `POST` | `/api/measure` | Distance (mm) between two points on a slice |
| `POST` | `/api/restore/toggle` | Toggle motion-artifact restoration on/off |
| `POST` | `/api/radiomics/analyze` | **Pathology classifier**: extract 14 biomarkers + classify 4 pathologies. Body `{patient_height_m}` → `biomarkers`, `biomarker_rows`, `diagnoses` |
| `POST` | `/api/radiomics/volumes` | **Standalone volume measurement**: segmented organ volumes only, no model. Body `{}` → `organ_volumes`, `total_cm3` |
| `POST` | `/api/ai/report` | SSE-streamed LLM report via OpenRouter. Body `{messages, model}`; requires `OPENROUTER_API_KEY` |

## Configuration

### segmentation_config.json

Maps 5 anatomical sectors to 81 TotalSegmentator organ classes:

| Sector | Count | Examples |
|--------|-------|----------|
| Skeleton | 25 | Skull, Vertebrae, Femur, Ribs, etc. |
| Gastrointestinal | 6 | Esophagus, Stomach, Colon, Bladder |
| Cardiovascular | 18 | Aorta, Heart chambers, Vena Cava |
| Other organs | 14 | Brain, Liver, Kidney, Lungs, Spleen |
| Muscles | 18 | Deltoid, Trapezius, Gluteus, Quadriceps |

### Biomarker display metadata (no UI hardcoding)

Two dictionaries at the top of `backend/radiomics_engine.py` drive everything the Biomarkers tab shows:

| Structure | Purpose |
|-----------|---------|
| `BIOMARKER_META` | One entry per biomarker: display label, unit, reference range → turned into table rows by `biomarker_rows()` |
| `DIAGNOSIS_META` | One entry per model key: display label + the biomarker that grounds its evidence string |

Adding a biomarker or a model = one dictionary entry; the API response and the React table follow automatically.

### Model bundle (`radiomics_pathology_engine.pkl`)

```python
{
    "models":   { "steatosis": XGBClassifier, "sarcopenia": XGBClassifier,
                  "hepatomegaly": XGBClassifier, "splenomegaly": XGBClassifier },
    "features": ["liver_vol_cm3", "liver_mean_hu", ..., "has_contrast"],  # 14 features, inference order
}
```

**Retraining** (from the repository root, after updating `backend/balanced_clinical_radiomics.csv`):

```bash
python compile_model.py
```

The script derives consensus clinical labels (ACR guidelines) when the CSV lacks label columns, fits one weighted `XGBClassifier` per pathology, and saves the `{models, features}` bundle. Because inference reads the feature order **from the bundle**, a new model is picked up without touching any application code.

### Backend Session State

Each session stores:

```python
{
    "array": np.ndarray,           # Current volume (may be restored)
    "original_array": np.ndarray,  # Original unmodified volume
    "is_restored": bool,           # Motion restoration active
    "spacing": tuple,              # Voxel spacing in mm
    "origin": tuple,               # Volume origin
    "direction": tuple,            # Direction cosines
    "mask": np.uint8 array,        # Segmentation mask (reset on every upload)
    "filename": str,               # Original filename
    "landmarks": dict,             # {organ_name: [z, y, x]} (reset on every upload)
    "label_colormap": dict,        # {label_id: (R, G, B)}
    "organ_to_label": dict,        # {organ_name: label_id} (populated after segmentation)
}
```

## Getting Started

### Web

```bash
# Terminal 1 - Backend
pip install -r backend/requirements.txt
pip install pandas joblib xgboost        # biomarker engine (model inference)
uvicorn backend.main:app --host 0.0.0.0 --port 8000

# Terminal 2 - Frontend
cd frontend
npm install
npm run dev
```

Open `http://localhost:3000` in your browser.

**Optional:**

```bash
pip install totalsegmentator   # AI organ segmentation (a threshold fallback is used otherwise)
```

Add `OPENROUTER_API_KEY=...` to `backend/.env` to enable the **Report** tab.

### Desktop

```bash
pip install PyQt5 vtk SimpleITK nibabel opencv-python numpy scipy
python -m backend.app
```

### Typical workflow

1. **Upload** a NIfTI / DICOM series / JPG / PNG file.
2. **Segment** (`Seg` tab) — run TotalSegmentator or the fallback segmenter; organ landmarks appear.
3. **Measure volumes** (`Biomarkers` tab → *Calculate Organ Volumes*) — standalone organ-volume table.
4. **Classify** (`Biomarkers` tab → *Run Pathology Classifier*) — 14 biomarkers → 4 pathology risk cards.
5. **Report** (`Report` tab) — streaming AI report with clickable organ landmarks.
6. **Explore** (`3D Lab` tab) — clip planes, organ layers, tissue presets.
7. Uploading another file starts you back at step 1 with **all results cleared**.
